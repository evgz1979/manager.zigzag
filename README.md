# Менеджер заказов «Зигзаг»

Версия для iPhone: [установка, работа без связи и ограничения](mobile/README.md). Исходники iOS 17+ и обработчик обмена готовы для проверки; сборка для устройства без подписи прошла в Xcode 27.1. Подпись, установка и настоящий iCloud ещё не проверены. На Mac обмен включается отдельно в разделе «iPhone · обмен».

Локальный просмотр папок клиентов и заказов. Код находится в ~/Documents/manager, документы остаются в своей папке на диске.

## Документация проекта

Постоянный справочник: **[документация проекта](docs/README.md)**. Основные разделы: [структура папок и исключения](docs/folder-structure.md), [хранение данных](docs/data-storage.md), [проверки, переносы и откат](docs/operations.md). Здесь ниже оставлены настройка и описание текущего интерфейса. Согласованные правила структуры и состояние их реализации указаны отдельно в справочнике.

## Настройка

Путь к документам задаётся в **[manager.ini](manager.ini)**, в секции [storage]:

    [storage]
    root = ~/Library/Mobile Documents/com~apple~CloudDocs/Зигзаг

    [server]
    host = 0.0.0.0
    port = 8765

root может быть абсолютным путём, путём с ~ или относительным путём от INI. После изменения настроек перезапустите сервер. Переменные ZIGZAG_DATA_ROOT и MANAGER_HOST, если заданы, переопределяют соответствующие настройки INI.

## Структура и интерфейс

- Папки клиентов лежат непосредственно в корне данных.
- Корневые папки с # показаны отдельными кнопками над деревом клиентов.
- Слева — раскрываемое дерево папок с фактической вложенностью на диске.
- Дерево показывает фактические папки на диске. Согласованная структура: клиент → объект → необязательный год → заказ → события и служебные папки; допустимые исключения описаны в документации.
- Вложенные папки с # остаются внутри своего клиента или заказа.
- Все папки с `#` и их подпапки — служебные. В них доступна только заметка: карточка заказа, статус, финансы и кнопка регистрации не показываются. `# bills` — счета для заказа, `# cdr` — файлы CorelDraw. Содержимое папок по-прежнему видно среди файлов родительского заказа.
- Справа — подпапки и все файлы выбранной папки, включая файлы из её подпапок. По умолчанию файлы сгруппированы по папкам; доступны поиск, фильтр по типу и сортировка.
- Фото (включая HEIC/TIFF), PDF, текст и поддерживаемые браузером видео и аудио можно смотреть внутри менеджера. Макеты и остальные форматы открываются в установленной программе на Mac.
- Статус и заметка сохраняются в обычном видимом файле «!.txt» внутри выбранной папки, доступном в том числе с iPhone. До регистрации заказа его можно редактировать без менеджера; после регистрации он обновляется из базы и предназначен для просмотра. При переходе к другой папке несохранённые изменения записываются автоматически.
- Скрытые файлы и символические ссылки не включаются в дерево и списки файлов.

Файл !.txt видимый в Finder и на iPhone; префикс «!» выделяет его при сортировке по имени. Менеджер исключает его из списков файлов: статус и заметка доступны в своей форме. Все данные карточки находятся в этом файле; остальные служебные файлы скрыты. Чтобы показать их в Finder, нажмите ⌘⇧. (Command + Shift + точка). Зарегистрированные заказы ведутся в локальной базе и автоматически выгружаются в каталоги документов; правила закреплены в AGENTS.md. В data/ находятся база с очередью выгрузки и технические кеши. Обычная работа менеджера сохраняет расположение пользовательских документов. Отдельно разрешённая раскладка выполняется с журналом переносов и откатом.

Прежние `!status.txt`, `!order.txt`, `.order.json`, `status.txt` и `.status.txt` объединяются в `!.txt`. После успешной записи их исходные байты сохраняются в скрытой `.order-history` внутри той же папки, затем прежние рабочие файлы убираются. Существующий `!.txt` сохраняет приоритет. Сверка версии формата автоматически ставит прежние выгрузки зарегистрированных заказов в очередь обновления.

При первом запуске прежние статусы из data/statuses.json переносятся в файлы соответствующих папок. Старый JSON сохраняется в корне документов как «.legacy-statuses.json»; несопоставленные записи остаются в этом архиве. Уже существующие файлы статуса не перезаписываются.

Формат `!.txt` — обычный UTF-8 с разделами:

    КАРТОЧКА ЗАКАЗА

    [Заказ]
    Название: Перегородки
    Статус: В работе

    [Финансы]
    Статус оплаты: Частично оплачен
    Сумма заказа: 100 000,00 ₽
    Затраты: 60 000,00 ₽
    Прибыль: 40 000,00 ₽
    Оплачено: 50 000,00 ₽
    Остаток оплаты: 50 000,00 ₽

    [Заметка]
    > Позвонить клиенту.
    > Согласовать размеры.

    [Служебное]
    Формат: 3

У зарегистрированной карточки служебный раздел также содержит идентификатор, версию и время изменения для восстановления базы. Отдельный JSON больше не нужен. Префикс `> ` у каждой строки заметки позволяет сохранить пустые строки и произвольный текст, даже похожий на заголовки разделов. Дополнительные блоки `[Замеры]`, `[Материалы]` и другие сохраняются в базе и при последующих выгрузках; формат подготовлен к их добавлению.

Для служебной папки новая заметка сохраняется в том же `!.txt`, с заголовком «ЗАМЕТКА ПАПКИ» и разделами `[Заметка]` и `[Служебное]`, без полей заказа. Файл можно редактировать вне менеджера. Прежние тестовые поля заказа убираются при открытии или сохранении заметки; заметка и дополнительные разделы остаются. Тестовые регистрации служебных папок удаляются из базы при запуске без выгрузки поверх файлов. Источник заметки — файлы папки. Счета, макеты и другие пользовательские документы не меняются.

## Общий список заказов и финансы

Согласованная структура документов: **клиент → объект → год (необязательно) → заказ по дате → события и служебные папки**. `2026-00-00` означает известный год, `2026-09-00` — известный месяц. Общие нумерованные папки и заказы (`00 - разное`, `00001 - …`) разрешены в корне и внутри клиента без привязки к объекту. При структурных проверках корневые `#…` полностью пропускаются; события и служебные папки не обходятся вглубь. Проверка с подсказками в интерфейсе — следующий этап.

Разрешённые пользователем переносы выполняются через `folder_layout.py` с журналом в скрытой `.folder-layout-history` внутри корня документов. Сеанс содержит `.before.json`, `.plan.json`, `.journal.jsonl`, `.after.json`, читаемый `.report.txt` и копию инструмента `.folder-layout.py`. Предварительный просмотр отката: `python3 folder_layout.py undo "путь-к-сеансу"`; выполнение — с `--apply`. Откат не перезаписывает существующие пути и не удаляет новые пользовательские данные. Все записи находятся рядом с документами; файл `.audit.txt` содержит замечания к структуре.

Главная страница «Все заказы» сохраняет дерево слева. Сверху — кнопки фильтра по производству, включая «В работе», «Переделка/доделка», «Готово», «Готово, но…» и «Отменён». Отдельное поле оплаты фильтрует по финансовому статусу: «Не указан», «На оплате», «Частично оплачен», «Оплачен». Производственный и финансовый статусы выбираются независимо и не меняются автоматически от сумм. Поиск работает по названию, пути и заметке; заголовки столбцов меняют сортировку. Итоги относятся к пересечению обоих фильтров и поискового запроса.

В таблице и карточке заказа доступны сумма, затраты и оплачено. Прибыль рассчитывается как сумма минус затраты, остаток оплаты — сумма минус оплачено; отрицательный остаток означает переплату. Пустое поле означает «не указано», ноль нужно вводить явно. Неполные итоги показывают количество заполненных заказов. Деньги сохраняются целыми копейками, ввод допускает запятую, точку и пробелы в разрядах.

Чтобы зарегистрировать заказ, откройте его папку и нажмите **«Добавить в список заказов»**. Карточка восстанавливается целиком из `!.txt`; прежние `!status.txt`, `!order.txt` и `.order.json` также учитываются при переносе. Глубина папки произвольная. Контекстное меню дерева оставлено на следующий этап.

Ошибочную регистрацию можно снять кнопкой **«Убрать из списка заказов»** в карточке заказа, после подтверждения. Папка, вложения, данные карточки и вложенные заказы сохраняются; в папке остаётся форма заметки. Повторный поиск не добавляет её обратно благодаря отметке `В списке заказов: нет` в `!.txt`. Вернуть папку в список можно вручную. Снятие регистрации и выгрузка сохраняются в локальной базе даже при временно недоступной папке.

Клиент, объект и группа года показывают заметку без предложения добавить заказ. Сервер проверяет роль папки при добавлении и поиске: заказы определяются по датам или номерам, годовые объединения и события не добавляются. Самостоятельная работа за год с событиями или материалами может быть заказом. Уже зарегистрированные по ошибке контейнеры сохраняют данные до ручного снятия с подтверждением.

Кнопка **«Найти заказы в папках»** запускает явный фоновый поиск: импортируются папки конкретных заказов с `!.txt`, прежним `.order.json` или файлами статуса. Папки без этих признаков не добавляются, вложения не читаются; обход внутри заказа прекращается. Папки с `#` на любой глубине, их поддеревья и символические ссылки пропускаются. Прогресс и ошибки видны на странице; существующие записи базы не заменяются. При копировании папки карточка получает отдельный идентификатор.

Локальная SQLite-база находится в `data/orders-<хеш-корня>.sqlite3`, отдельно от iCloud. У разных корней документов разные базы. Загрузка списка, поиск, фильтры и сохранение зарегистрированной карточки не сканируют iCloud. Зарегистрированная карточка открывается из базы сразу, даже при недоступной папке; файлы догружаются отдельно в фоне, не сбрасывая ввод. Дерево загружается отдельно, по уровням; просмотр файлов по-прежнему читает выбранную папку и её подпапки.

Изменения сначала фиксируются в базе, затем автоматически выгружаются в единственный **`!.txt`** в папке заказа. Он содержит оба статуса, заметку, название, все финансовые показатели и сведения для восстановления базы. Другие рабочие файлы карточки не создаются.

У зарегистрированного заказа `!.txt` служит копией для просмотра; редактируйте карточку через менеджер. До регистрации он учитывает внешние правки статуса и заметки. Файл исключён из списка вложений программы.

При недоступной папке изменения остаются в базе, а очередь и ошибка выгрузки видны в таблице. Повторная попытка выполняется каждые 15 секунд, при запуске сервера и по кнопке **«Выгрузить в папки»**. Запись `!.txt` атомарная; прежние файлы архивируются только после её успеха. База использует версии карточек для защиты от сохранения устаревшей вкладки.

**Не удаляйте `data/` при ожидающей выгрузке:** там хранится актуальная версия изменений. После успешной выгрузки список и финансовые данные восстанавливаются кнопкой поиска карточек. «Выгружено» означает запись на локальный диск; передачей файлов в облако управляет iCloud.

Карточка заказа занимает половину рабочей области, рядом расположен To-do. Задачи можно добавлять, редактировать, отмечать выполненными и удалять; изменения сохраняются автоматически вместе с заказом. Список и отметки выгружаются в раздел `[Задачи]` единого `!.txt` как `- [ ]` и `- [x]`, восстанавливаются из папки и не влияют на статусы. На узком экране To-do переносится под карточку.

В окне просмотра любого файла есть поле **«Комментарий к файлу»**, включая макеты и другие форматы без встроенного просмотра. В сетке под превью показывается мелкое имя файла, ниже — комментарий; размер, дата и кнопки не показываются, пустой комментарий места не занимает. Сохранение — кнопкой, ⌘S/Ctrl+S, при закрытии или переключении файла. Комментарий хранится обычным текстом в скрытой `.file-comments` рядом с оригиналом; прежние версии остаются в `.history`, исходный документ не меняется. Внешние изменения учитываются, устаревший комментарий не перезаписывается поверх них.

При просмотре файла слева показан **«Комментарий к папке»** только для чтения и копирования — тот же текст, что в поле «Заметка» открытой папки. В центре остаётся просмотр, справа — редактируемый комментарий к файлу. Общая заметка служит контекстом и при переходе между файлами из подпапок; на узком экране блоки идут друг под другом.

## PDF-отчёты по изображениям

В углу каждой карточки файла есть чекбокс. Над сеткой можно выбрать все файлы текущего фильтра и нажать **«PDF-отчёт»**. В отчёт попадут только выбранные изображения с полными комментариями; остальные типы пропускаются. На A4 размещается до четырёх изображений в сетке 2×2. В PDF встраиваются JPEG-копии до 1200 пикселей по длинной стороне с качеством 72%; исходные файлы и их разрешение не меняются. Длинные комментарии продолжаются в следующих ячейках и страницах. PDF сохраняется в открытой папке как `report - ГГГГ-ММ-ДД.pdf`, при повторе — с номером. До 200 изображений в отчёте; результат можно сразу открыть кнопкой в панели.

## Удаление выбранных файлов

Для выбранных файлов доступно **«Удалить»** с подтверждением полного списка. Файлы и комментарии перемещаются в корзину менеджера с журналом; кнопка **«Корзина»** позволяет вернуть их после перезапуска. Существующие файлы при восстановлении не перезаписываются. Это корзина внутри документов, отдельная от системной Корзины macOS; автоматической очистки нет.

## Задания на широкоформатную печать

Для папки **# work/# print** используется отдельный редактор заданий. Пробел после # необязателен: #work/#print и смешанные варианты распознаются одинаково.

- Слева внутри страницы — список текстовых заданий; справа — отдельные поля названия, ссылки на файлообменник и описания.
- Кнопка «Новое задание» открывает новый документ. Файл появляется после сохранения или перехода с заполненного задания.
- Имя файла: print - ГГГГ-ММ-ДД, дата по московскому времени. Расширение берётся из существующего образца; сейчас это .textClipping. При совпадении имени добавляется (2), (3) и далее. Название задания редактируется внутри файла и не меняет его имя.
- Ссылка записывается первой строкой, затем строка «Название: …» и описание, разделённые пустыми строками. Ссылка и название необязательны. В старом задании с заголовком перед ссылкой оба выделяются в отдельные поля; открытие и сохранение без правок не меняют исходный файл.
- Описание пока заполняется вручную. Над ним оставлена неактивная кнопка «Сканировать папки и заполнить описание» с пометкой «Позже» — напоминание о будущей функции.
- Поддерживаются текстовые вырезания macOS (.textClipping), TXT, TEXT, Markdown, RTF и текстовые файлы без расширения. Редактор работает с обычным текстом; при изменении RTF и вырезаний форматирование упрощается.
- Сохранение кнопкой или ⌘S; при переходе в другую папку или к другому заданию изменения сохраняются автоматически.
- Перед записью проверяется, не изменился ли файл в другой программе. Прежнее содержимое сохраняется рядом с заданием в папке «.print-history», внутри подпапки с именем файла. История доступна в Finder и исключена из списка активных заданий в менеджере.

## Запуск

В Launcher (~/Documents/launcher) выберите **Менеджер заказов → Start Веб-интерфейс**. Остановка: **Stop all in Менеджер заказов**.

В Terminal:

    cd ~/Documents/manager
    python3 server.py

Откройте http://127.0.0.1:8765. Порт можно переопределить аргументом: python3 server.py 8766.

При host = 0.0.0.0 менеджер также доступен в локальной сети по адресу http://<IP-адрес-Mac>:8765, без авторизации. Действие «Открыть на Mac» открывает файл на компьютере, где работает сервер.

Launcher использует launcher.json. При смене порта обновите также port и url в нём. Команда Launcher и start.command используют порт из INI.
