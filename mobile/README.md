# Зигзаг для iPhone — первая версия

> Обмен отложен по решению пользователя. Обработчик Mac приостановлен, включение недоступно; данные и очередь сохранены. Инструкции ниже описывают прежний протокол и потребуют адаптации к хранению в SQLite.

Исходники отдельного приложения для iOS 17 и новее и обработчик обмена Mac готовы для проверки. **Сборка для настоящего устройства iOS без подписи прошла в Xcode 27.1 (27A9275). Подпись, установка на телефон и реальный обмен через iCloud ещё не проверены.** Xcode установлен на внутреннем SSD в `/Applications/Xcode.app`; внешний диск для сборки не нужен. Успешная сборка не заменяет проверку двух устройств.

## Что есть

- Список заказов с поиском, карточки, производственный и финансовый статусы, суммы и заметки для чтения.
- Добавление комментариев к заказам и отдельным файлам; прежний текст дополняется, статусы и суммы не меняются.
- To-do: добавление задач и отметка выполнения. Старый нераспознанный раздел задач остаётся для чтения.
- Карточки, вводимые черновики и очередь изменений сохраняются на телефоне. Работа с полученными данными не требует сети или включённого Mac.
- Фото, PDF и другие поддерживаемые Quick Look документы можно заранее сохранить для просмотра без связи. В первой версии — по одному файлу до 100 МБ, без автоматической загрузки всего архива.
- Статус обмена и сохранённые операции, включая конфликты, доступны во вкладке «Изменения».

## Установка

1. Установить полный **Xcode** из Mac App Store и запустить его для первоначальной настройки. Одних Command Line Tools недостаточно.
2. Открыть `mobile/ZigzagPhone.xcodeproj`. Выбрать цель `ZigzagPhone`, раздел **Signing & Capabilities**, включённое **Automatically manage signing** и свою **Personal Team**. При необходимости задать уникальный **Bundle Identifier**. Использовать затем тот же идентификатор, чтобы обновлять уже установленное приложение с сохранением данных.
3. Подключить iPhone к Mac, выбрать его устройством запуска, подтвердить доверие и включить Developer Mode, если Xcode/iPhone попросят. Нажать **Run**.
4. При бесплатном Apple ID подпись действует **7 дней**, затем нужно снова собрать и установить приложение из Xcode. Не удалять приложение перед обновлением: в нём могут быть непереданные изменения. Этот способ подходит для тестирования; постоянная установка требует отдельного решения о распространении.

Приложение не использует CloudKit и не требует собственного iCloud-контейнера: доступ к выбранной папке выдаётся системным диалогом «Файлы». Подпись приложения и Apple ID в Xcode всё равно нужны.

Официальные сведения: [бесплатная Personal Team и срок подписи](https://developer.apple.com/help/account/basics/about-your-developer-account), [доступ iOS-приложения к выбранной папке](https://developer.apple.com/documentation/uikit/providing-access-to-directories).

## Первый обмен

1. Перезапустить сервер менеджера после обновления кода. В браузере на Mac открыть **«iPhone · обмен» → «Подготовить обмен»**. Дождаться времени успешной подготовки и числа заказов.
2. Дать iCloud передать служебные файлы внутри «Зигзаг». Успех записи на Mac ещё не означает завершение облачной передачи.
3. В приложении iPhone открыть **«Настройка» → «Выбрать папку “Зигзаг”»**, выбрать именно корень «Зигзаг» в iCloud Drive, затем **«Синхронизировать»**. Для первой загрузки нужна связь.
4. Открыть нужные заказы. Если нужны оригиналы без интернета, зайти в файл и нажать **«Сохранить для просмотра без связи»**, затем проверить **«Открыть сохранённую копию»**. Скачанные оригиналы хранятся в Application Support, а не в очищаемом системном кеше.

Проверка перед реальной работой: включить авиарежим, добавить тестовый комментарий и задачу, отметить выполнение, закрыть и снова открыть приложение. Убедиться, что ввод сохранился. Вернуть связь, запустить менеджер на Mac, выполнить обмен на обоих устройствах и дождаться подтверждения. Повторить обмен и проверить отсутствие дублей. Отдельно проверить при выключенном Mac и после переименования задачи или замены файла.

## Как работает обмен

Рабочая SQLite-база остаётся в локальном `data/`. При включённом обмене отдельный фоновый обработчик Mac раз в минуту готовит каталог и принимает операции. Список файлов заказа обновляется не чаще раза в пять минут, после мобильного комментария к файлу — при следующей подготовке. В карточке указано отдельное время списка файлов и ошибка, если обновление не удалось. Это фоновая работа, не часть чтения таблицы заказов из базы.

Телефон синхронизируется при открытии приложения, раз в минуту пока приложение активно и по кнопке. Время работы закрытого приложения не гарантируется. Если iCloud недоступен, можно продолжать читать ранее полученные карточки и вводить текст; повторить обмен позже. «Сохранено для передачи» означает публикацию файла на устройстве, **не подтверждение облачной доставки**. Только подтверждение из нового каталога Mac означает применение. Пока Mac выключен, записи ждут его запуска.

В `.mobile-sync` внутри «Зигзаг» находятся читаемые UTF-8 JSON-файлы:

| Путь | Назначение |
| --- | --- |
| `.identity.json` | Устойчивый идентификатор архива |
| `.catalog.json` | Каталог для чтения: карточки, список вложений, комментарии, задачи, подтверждения |
| `.inbox/.<UUID>.json` | Отдельное неизменяемое действие с телефона |
| `.receipts/.<UUID>.json` | Подтверждение применения или сохранённый конфликт |

Это формат обмена, не новая карточка заказа и не резервная копия SQLite. Прежний `!.txt` сохраняет своё назначение. В самой SQLite находятся идентичности/версии задач и журнал применения. Комментарий заказа сначала фиксируется в базе; комментарий файла — с прежней историей в `.file-comments`. Удалять базу с невыгруженными изменениями по-прежнему нельзя.

Повторная доставка одного действия не повторяет добавление. Задачи сопоставляются по идентификатору и версии, а не только по тексту или номеру строки. Переименованная, удалённая или неоднозначная задача вызывает конфликт. Совпавший желаемый признак выполнения не снимается повторным действием. Комментарий к заменённому или переименованному файлу не привязывается к другому документу автоматически. Сохранённые конфликтующие действия и их тексты доступны на телефоне; в первой версии их можно скопировать и разобрать вручную. Автоматического удаления очереди и истории нет.

При восстановлении базы из `!.txt` сохранить `.mobile-sync`: подтверждения защищают от повторного применения старых действий, идентификатор защищает от смешивания архивов. Идентификаторы задач из прежней базы при таком восстановлении могут измениться; ожидающие отметки требуют разбора, их текст остаётся в очереди.

## Проверки разработки

Из корня проекта:

```sh
python3 -m unittest discover -s tests -v
sh mobile/check.sh
python3 mobile/protocol_check.py
```

Сборка для устройства без подписи, не требующая симулятора:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project mobile/ZigzagPhone.xcodeproj -scheme ZigzagPhone \
  -destination 'generic/platform=iOS' -configuration Debug \
  -derivedDataPath data/ios-build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

Для проверки локального ядра Swift нужен установленный Swift и macOS SDK. `check.sh` проверяет устойчивое сохранение, перезапуск, зависимости задач, подтверждения, старый каталог, другой архив и повреждение состояния; проверка экрана iOS в нём только синтаксическая.
