# JavaScript: состояние, DOM и асинхронные действия

## Обычные скрипты и области видимости

В [index.html](../../static/index.html) скрипты подключены последовательно, без `type="module"`. Верхнеуровневые объявления живут в общем окружении страницы. Порядок имеет значение: `app.js` использует заранее объявленные календарь/сортировку, а последующие компоненты обращаются к его `state`, `request`, `notify` и другим функциям.

IIFE вида `const HomeCalendar = (() => { ...; return { show, ... }; })()` выполняется сразу, создаёт замыкание и наружу возвращает только объект доступных операций. Переменные `range`, `orders`, таймеры и измеренные высоты сохраняются между вызовами в этом замыкании. Это локальное состояние модуля, хотя файл не ES-module.

Функция-стрелка использует лексический `this`; обычная функция получает `this` по способу вызова. Большинство компонентов использует явные замыкания и аргументы, поэтому изменение формы объявления без проверки может поменять обработчики. Анонимные event callbacks документируются в контексте именованной операции, а не получают искусственное имя ради справочника.

## Общий state и DOM

`state` в [renderFolder](../reference/javascript/static-app.md#symbol-renderFolder) и связанных функциях — обычный изменяемый объект. Изменение `state.orders` само по себе не обновляет экран: после него вызывается нужная render-функция. И наоборот, ввод в `<textarea>` не становится сохранённым серверным полем без явного сбора значений.

`innerHTML` заменяет узлы и может потерять фокус, выделение, прокрутку и локальные свойства. `textContent` записывает текст без HTML-интерпретации. [escapeHtml](../reference/javascript/static-app.md#symbol-escapeHtml) нужен, когда пользовательский текст включается в HTML-строку; URL-параметры дополнительно кодируются через `URLSearchParams`/`encodeURIComponent`.

`dataset` хранит строковые атрибуты `data-*`; число/revision из него нужно проверять и приводить явно. Делегирование событий на контейнер позволяет обрабатывать новые строки после рендера, но `event.target` может оказаться SVG-вложением кнопки. Поэтому обработчик ищет нужный `closest(...)`, а не предполагает, что нажат всегда сам `<button>`.

## Promise, async/await и отказ

[request](../reference/javascript/static-app.md#symbol-request) вызывает `fetch`, читает JSON и проверяет `response.ok`. Сам `fetch` не превращает HTTP 409 в rejected Promise: это делает обёртка. `await` приостанавливает текущую async-функцию, но не блокирует интерфейс браузера.

```javascript
try {
  const saved = await request('/api/order-calendar-compact', payload);
  // Только подтверждённое состояние можно принять как сохранённое.
} catch (error) {
  // Черновик и выбранное действие остаются для явной проверки.
}
```

Это поясняющий пример протокола, а не готовый обработчик: настоящий payload и применение ответа смотри в [toggleCalendarCompact](../reference/javascript/static-app.md#symbol-toggleCalendarCompact). `finally` снимает busy даже при ошибке, но не должен автоматически повторять POST.

Одновременные запросы могут завершиться в другом порядке. Компонент проверяет, что ответ относится к всё ещё открытой папке/записи, и не подставляет его в другую форму. Локальный busy защищает пользовательскую последовательность, UUID/revision на сервере защищают само хранилище от другой вкладки.

## Черновик и базовая версия

Нужно различать серверный снимок, редактируемый текст и revision, на основе которой открыт редактор. Фоновый poll может обновить список, но не повышать revision несохранённой формы так, будто пользователь уже видел новую запись.

Пример точной частичной формы — [saveText](../reference/javascript/static-supplier-purchases.md#symbol-saveText). Она отправляет не только новый текст, но и исходный текст, индекс, путь/UUID/revision заказа и раздел поставщика. [checkText](../reference/javascript/static-supplier-purchases.md#symbol-checkText) перечитывает источник без замены введённого черновика. Сервер решает, можно ли ещё доказать идентичность строки.

`localStorage` хранит настройки браузера, например сворачивание групп. Это не резервная копия заказов и не замена SQLite. У другой машины/браузера будет собственное состояние интерфейса.

## Гражданские даты и календарь

`Date` представляет момент времени, но бизнес-ключ `2026-11-02` — гражданскую дату. [moscowDate](../reference/javascript/static-home-calendar.md#symbol-moscowDate) извлекает год/месяц/день через `Intl.DateTimeFormat(..., timeZone: 'Europe/Moscow')`, затем помещает их в `Date.UTC`. Далее UTC-методы служат арифметике дней без случайного сдвига в локальный часовой пояс браузера.

[monday](../reference/javascript/static-home-calendar.md#symbol-monday) вычитает смещение дня недели; [weekNumber](../reference/javascript/static-home-calendar.md#symbol-weekNumber) считает ISO-неделю через четверг. Ключ недели — дата понедельника, а не строка с одним номером недели. Это сохраняет различие одинаковых номеров в разных годах.

[visibleOrderWeeks](../reference/javascript/static-home-calendar.md#symbol-visibleOrderWeeks) проверяет срок и события, отдельно выполнение и неактуальность. `null` в неизвестном наборе событий сохраняет доступность строки. `calendarRange` хранит явные ключи недель: закрытые прошлые промежутки пропускаются, поэтому индекс DOM больше не равен смещению от первой даты на семь дней. Переключатель «Старые» изменяет только состояние замыкания; снимок использует обычную фильтрацию независимо от него. Преобразование `null` в `{}` на раннем этапе потеряло бы эту защиту.

[measureWeeks](../reference/javascript/static-home-calendar.md#symbol-measureWeeks) измеряет высоту каждой недели; [fitViewport](../reference/javascript/static-home-calendar.md#symbol-fitViewport) подгоняет окно под две полные недели. Изменение наполнения требует новых измерений и сохранения выбранного ключа недели, а не просто восстановления прежнего scrollTop в пикселях.

## Таймеры и окно To-do

У календарного окна несколько независимых событий: первое наведение, переход на соседнее событие, уход мыши, фокус и явное закрепление. [hoverCalendarTodoPreview](../reference/javascript/static-app.md#symbol-hoverCalendarTodoPreview) и [scheduleCalendarTodoPreviewClose](../reference/javascript/static-app.md#symbol-scheduleCalendarTodoPreviewClose) используют разные таймеры. [cancelCalendarTodoPreviewSwitch](../reference/javascript/static-app.md#symbol-cancelCalendarTodoPreviewSwitch) отменяет ожидающую смену заказа при входе в окно.

`setTimeout` планирует callback, но не гарантирует точный момент выполнения при занятом event loop. `clearTimeout` отменяет ещё не сработавшую задачу. Закрытие окна должно отменять связанные таймеры, иначе оно может открыться снова из старого callback.

Фокус и нажатие значка открывают окно сразу; закреплённое окно не следует за соседним наведением. Источник задачи сохраняется отдельно от текущей строки под мышью, поэтому кнопка «Открыть заказ» остаётся связанной с правильным событием.

## Меню узкого экрана

[setOpen](../reference/javascript/static-navigation.md#symbol-setOpen) управляет открытием боковой панели, затемнением, блокировкой фона и возвратом фокуса. Существующие узлы панели сохраняются, чтобы не терять строку поиска и прокрутку. Смена ширины должна снять мобильную блокировку, если панель стала обычной широкой колонкой.

Это управление DOM и доступностью; к данным заказов оно не относится. Загрузка новой папки и раскрытие ветки — разные события: только успешный переход закрывает меню.

## Worker и Excel

`new Worker(...)` создаёт отдельный JS-контекст без DOM страницы. Сообщения передаются через `postMessage`; идентификатор запроса позволяет связать ответ с текущей операцией. Worker загружает локальный SheetJS через `importScripts`, получает байты `/api/spreadsheet`, разбирает книгу и возвращает ограниченную страницу данных.

[page](../reference/javascript/static-spreadsheet-worker.md#symbol-page) ограничивает 10000 строк и 256 колонок, возвращает не более 200 строк за порцию и уменьшает их число для широких таблиц. Форматирование ячейки учитывает сохранённый текст, числовой формат и Excel date1904. Макросы не загружаются как исполняемый код; формулы не вычисляются. Книга не переписывается.

Остановка/закрытие просмотрщика должна освобождать Worker и связанные обработчики. Ошибка защищённой книги — отдельное состояние интерфейса, а не пустой успешный лист.

## PNG как отдельное представление

[createSnapshot](../reference/javascript/static-home-calendar.md#symbol-createSnapshot) создаёт отдельный DOM снимка нужного периода. [capture](../reference/javascript/static-calendar-snapshot.md#symbol-capture) лениво загружает локальный html2canvas, применяет размеры копии и получает Blob PNG. Рабочая сетка и выбранный период не должны перепрыгивать вслед за экспортом.

Для команды Telegram [html](../reference/python/calendar_delivery.md#symbol-html) включает те же модули в автономный HTML, а `calendar_renderer.swift` запускает его в отдельном WebKit. Здесь есть именованная функция `makeCalendar` внутри Python HTML-шаблона: она относится к встроенному сценарию рендера и описана вместе с `calendar_delivery.html`, а не является отдельным `static/*.js` модулем.

## Истёкшая внешняя сессия

[requireLogin](../reference/javascript/static-remote-access.md#symbol-requireLogin) показывает ссылку входа в новой вкладке. Обёртка `window.fetch` замечает 401 с `X-Manager-Login: required`, но возвращает исходный ответ вызывающему коду. Черновик остаётся; POST не ставится в скрытую очередь повторов. После возврата на видимую вкладку отдельная проверка сессии убирает уведомление при успешном входе.

[Справочник JavaScript](../reference/README.md#javascript) содержит именованные функции, методы объектов и функции, присвоенные именованным переменным. Анонимные callbacks рассматриваются в теле владельца. Сторонний минифицированный код исключён.
