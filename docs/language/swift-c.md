# Swift, C и системный запуск

## Помощник как отдельная программа

Корневые `.swift` — небольшие macOS-программы, а не загружаемые Python-модули. Python собирает исполняемый файл через `swiftc`, затем передаёт аргументы или JSON/HTML в stdin. Готовые байты идут в stdout; диагностические сообщения — в stderr; ненулевой exit code означает отказ. Добавление отладочного `print` в stdout может повредить PDF, PNG или JSON-протокол.

Swift разрешает исполняемые операторы на верхнем уровне файла. Поэтому `icloud_read.swift` может не иметь объявленной функции `main`: после импорта модулей сразу выполняется `do/catch` с чтением аргументов и файла. Отсутствие класса не делает такой файл неиспользуемым.

[build](../../native_renderers.py#L10) вычисляет хеш всего исходника, собирает в отдельный временный путь и публикует готовый бинарный файл. Канонический module cache исключает несовпадающие абсолютные пути `data` разных релизов. Имя бинарного файла связано с содержимым, а не только с mtime.

## Foundation и iCloud

`URL(fileURLWithPath:)` задаёт файловый URL, `FileManager` проверяет атрибуты, `NSFileCoordinator` согласует чтение с iCloud и другими участниками файловой системы. Координация не равна бесконечному ожиданию успешного скачивания; Python задаёт внешний timeout.

В [icloud_read.swift](../../icloud_read.swift) проверяются число аргументов, допустимый предел до 20 МиБ, обычный файл, размер до и во время чтения. `FileHandle.read(upToCount: limit + 1)` позволяет обнаружить превышение ограничения, даже если файл вырос после stat. Ошибки координации и чтения сохраняются отдельно, после callback проверяются и переводятся в отказ процесса.

`defer` выполняет освобождение ресурса при выходе из текущей области. Например, закрытие FileHandle происходит и при `throw`. `guard ... else { throw ... }` прекращает неверный сценарий до использования неподтверждённых значений. Optional `Data?` обозначает, что callback мог не вернуть содержимое; отсутствие не превращается в успешный пустой файл.

## AppKit, PDFKit и Core Graphics

`Data` содержит байты, `String` — Unicode-текст, `CGImage` — декодированное изображение. Преобразование между ними требует явного декодера/кодировщика. В `thumbnail_preview.swift` ImageIO кодирует JPEG; исходное изображение при этом не сохраняется поверх себя.

`pdf_preview.swift` использует PDFKit для открытия документа, получения информации и рендера выбранной страницы. Ограничения и кеш Python относятся к производному изображению страницы, а не к редактированию PDF. Отдельный `invoice_pdf.swift` выполняет раскладку счёта/договора и извлечение текста для определения однозначного итога внешнего PDF.

[attributed](../../invoice_pdf.swift#L44) создаёт `NSAttributedString` с нужным шрифтом и выравниванием. [text](../../invoice_pdf.swift#L53) измеряет текст и сохраняет геометрию; [layout](../../invoice_pdf.swift#L68) рассчитывает содержимое до финального рисования. Нельзя менять только размер шрифта на этапе вывода: измеренная высота перестанет соответствовать фактическим строкам.

[nextCell](../../image_report.swift#L44) размещает до четырёх изображений на A4 со связанными комментариями. Чтение комментариев и проверка исходных абсолютных путей выполняются вызывающим Python, поэтому Swift-помощник не должен самостоятельно расширять файловую область.

## WebKit-календарь

[CalendarRenderer](../../calendar_renderer.swift#L13) наследует NSObject и реализует протоколы навигации и сообщений WebKit. Это делегирование: WKWebView вызывает методы `webView` и `userContentController` при соответствующих событиях.

В `init` создаётся `WKWebViewConfiguration` с `.nonPersistent()` хранилищем. Помощник не использует вкладку пользователя и её cookies. Навигационный делегат разрешает только нужную локальную схему; автономный HTML включает CSS/JS/данные непосредственно. После загрузки `evaluateJavaScript` вызывает `makeCalendar`.

Результат приходит через `window.webkit.messageHandlers.calendar.postMessage`. Swift проверяет словарь, base64 и размер до 10 МиБ, пишет PNG и завершает процесс. Верхний уровень запускает AppKit run loop и отдельный таймаут; Python также ограничивает процесс по времени. Успешная загрузка HTML ещё не считается успешным созданием PNG.

## Сохранённое приложение iPhone

Приложение в `mobile/` **приостановлено со стороны рабочего Mac**. Следующее описание относится к сохранённой реализации, а не к доступной сейчас функции синхронизации. Обзор статуса — в [mobile/README.md](../../mobile/README.md).

`struct PhoneTask`, `PhoneOrder`, `PhoneOperation` и другие типы реализуют `Codable`: `JSONEncoder`/`JSONDecoder` переводят их в байты/из байтов. Codable проверяет типизацию полей, но не все бизнес-ограничения: [PhoneStore.ingest](../../mobile/Core.swift#L243) дополнительно проверяет схему, UUID, уникальность, безопасные пути и принадлежность архиву.

Структуры имеют семантику значения. `var next = state` создаёт новое логическое состояние; [PhoneStore.persist](../../mobile/Core.swift#L154) сначала сохраняет его на диск, затем принимает в память. `final class PhoneStore` — ссылочный объект, вокруг которого строится устойчивый локальный редактор. Повреждённое состояние не должно автоматически заменяться пустой очередью.

`QueuedOperation` хранит точные байты сериализации один раз. Digest подтверждения считается от этих байтов. Повторное кодирование того же логического JSON могло бы изменить порядок/формат и нарушить совпадение receipt.

[PhoneStore.order](../../mobile/Core.swift#L295) накладывает неподтверждённые локальные действия на последнюю карточку каталога. Это представление для чтения; оно не означает, что Mac уже принял изменение. `sent` означает публикацию операции в локальную папку iCloud, `receipt` — подтверждённое применение/конфликт.

## Actor и MainActor

`actor DriveTransport` изолирует изменяемое состояние транспорта и согласованное файловое чтение от UI. `await` в [PhoneModel.sync](../../mobile/PhoneApp.swift#L94) позволяет дожидаться работы транспорта, не выполняя её в обычном синхронном обработчике поля.

`@MainActor` у UI-модели задаёт место изменения наблюдаемого состояния SwiftUI. Это не утверждение, что любая операция внутри async-функции автоматически выполняется в фоне. Блокирующий файловый код специально вынесен в транспорт.

`security-scoped bookmark` сохраняет выданное пользователем разрешение на папку. `startAccessingSecurityScopedResource` открывает область, `defer` закрывает её. Перед копированием вложения транспорт проверяет компоненты пути, отсутствие символических ссылок, размер и версию файла.

`UIViewControllerRepresentable` связывает SwiftUI с системным picker и Quick Look. `Coordinator` реализует UIKit-делегат. Пустой `updateUIViewController` — сознательный обязательный хук, а не забытая бизнес-операция. Вычисляемый `var body: some View` — свойство построения экрана; именованные типы/методы описаны в справочнике, свойства читаются в контексте их типа.

## C-обёртка launchd

[scripts/manager_launcher.c](../../scripts/manager_launcher.c) обеспечивает постоянную macOS-идентичность приложения при запуске Python. Это важно для разрешения доступа к iCloud-папке: доступ SSH-сессии сам по себе не доказывает доступ фонового приложения.

[authorize](../../scripts/manager_launcher.c#L20) проверяет каталог через `opendir`, закрывает его и возвращает диагностический код. [main](../../scripts/manager_launcher.c#L32) либо выполняет авторизацию каталогов, либо делает `fork`. В дочернем процессе `execv` заменяет процесс на Python с `-u`; в родительском обёртка ожидает ребёнка через `waitpid`.

`forward_signal` передаёт SIGTERM/SIGINT дочернему PID. `waitpid` повторяется после EINTR; код завершения ребёнка возвращается launchd. При сигнале возвращается `128 + signal`. Это отличается от запуска Python через короткоживущую shell-команду, которая не сохранила бы нужный жизненный цикл приложения.

## Проверки и их пределы

`mobile/check.sh` проверяет типы локального ядра/транспорта, запускает `CoreTests.swift`, синтаксически разбирает PhoneApp для iOS и проверяет pbxproj. Это не установка на физический iPhone и не реальная доставка iCloud. `mobile/protocol_check.py` сверяет сохранённый протокол на временном архиве.

Сборка macOS-помощников проверяет доступность SDK и типы; отдельно нужны функциональные тесты байтов/страниц и изолированного календаря. Изменение комментариев не должно менять исполняемые токены; для этого документационного среза выполнена отдельная проверка неизменности кода.
