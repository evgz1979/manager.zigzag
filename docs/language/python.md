# Python: от HTTP до сохранения

## Модуль и момент исполнения

`import orders` исполняет верхний уровень `orders.py` один раз на процесс и сохраняет объект модуля. `from orders import OrderStore` привязывает имя класса в вызывающем модуле. Это не создание экземпляра и не копирование базы. Локальные `import` внутри методов используются для зависимостей, которым не нужно загружаться при каждом импорте верхнего уровня; такие импорты тоже учитываются при чтении архитектуры.

У `server.py` есть существенный побочный эффект импорта: `DATA_ROOT, SERVER_HOST, SERVER_PORT = read_config()` вычисляются на верхнем уровне. Поэтому тест, импортирующий сервер, должен подготовить окружение до импорта или явно подменить нужные значения. `if __name__ == "__main__": main()` запускает сервер только при прямом исполнении файла, но не отменяет уже выполненное чтение конфигурации.

Константа `DATABASE_ONLY = True` выбирает текущую модель хранения. Наличие параметра `database_only=False` в тесте адаптера не означает, что рабочий сервер запускает эту ветку. [Реестр совместимости](../legacy-code.md) перечисляет такие места.

## Класс, экземпляр и зависимости

[OrderStore](../../orders.py#L34) — класс. Вызов `OrderStore(root, data_dir, labels, database_only=True)` создаёт экземпляр и вызывает `__init__`. `self.root`, `self.database` и `self.labels` принадлежат экземпляру. Метод `store.get(path)` не получает `self` явно от пользователя: Python связывает его автоматически.

Фабрика [order_store](../../server.py#L804) создаёт адаптер по текущим глобальным настройкам. Это лёгкий объект доступа, а не одна глобально открытая SQLite-сессия. Другие адаптеры получают его как зависимость: например, `MetadataStore(store)` использует тот же путь базы и корень. Наследование [ObjectActivity](../../object_activity.py#L13) от `ClientActivity` переиспользует контракт индекса, меняя правила поиска объектов.

Исключение `OrderConflict(ValueError)` — отдельный тип для различения конфликта от обычного неверного ввода. `except OrderConflict` должен идти по подходящей ветке обработки; перехват только общего `ValueError` потерял бы HTTP-смысл 409.

## Контекстный менеджер и транзакция

[OrderStore.connect](../../orders.py#L48) помечен `@contextmanager`. Функция с `yield db` становится протоколом входа/выхода:

```python
with store.connect() as db:
    db.execute("SELECT * FROM orders WHERE path=?", (relative,))
```

До `yield` создаются соединение и необходимая схема. После выхода выполняются контекст SQLite и `finally: db.close()`. При исключении управление всё равно выходит через освобождение ресурса. Возврат из середины `with` также вызывает выход, поэтому нельзя считать ранний `return` способом обойти commit/rollback.

`with db` управляет транзакцией, но не закрывает соединение. `contextlib.closing` в backup-утилитах решает именно закрытие. Это две разные обязанности. `BEGIN IMMEDIATE` заранее получает право на запись и позволяет проверить текущую версию в той же транзакции, в которой выполняется UPDATE.

В [OrderStore.save](../../orders.py#L231) сравниваются путь/UUID/revision. После проверки сохраняются конкретные поля и новая revision. При исключении незавершённые SQL-изменения откатываются. Выполненный до исключения внешний файловый перенос SQLite автоматически не отменяет: для него нужен собственный журнал.

## Строгие значения и три состояния

В Python `bool` является подтипом `int`. Поэтому `isinstance(True, int)` недостаточно для проверки целой revision или версии JSON. Строгие контракты используют `type(value) is int`/`type(value) is bool` там, где ложное числовое значение могло бы пройти как отметка.

[read_compact](../../calendar_layout.py#L10) различает:

| Результат | Значение |
| --- | --- |
| `False` | Блок отсутствует или известная отметка выключена |
| `True` | Известная отметка включена |
| `None` | Сохранённый блок есть, но его формат неизвестен/повреждён |

`None` здесь не разрешает сохранить `False`. [write_compact](../../calendar_layout.py#L26) отказывает при неизвестном прежнем формате. Точно так же неизвестный список задач нельзя превращать в `[]` только ради удобства формы.

Словарь `{**blocks, NAME: new_value}` создаёт новый верхний словарь с заменой одного ключа. Это неглубокая копия: вложенные изменяемые объекты сохраняют ссылки. В блоках карточки значения обычно строки, поэтому преобразователи возвращают новый набор блоков, а вызывающее хранилище отдельно сериализует его в SQLite.

## Парсинг, деньги и Unicode

[parse](../../order_document.py#L337) разбирает прежнюю читаемую карточку, сохраняя дополнительные неизвестные блоки. Парсер и рабочая запись базы — разные уровни. Функция может применяться к первоначальному файлу и к тексту блока из SQLite; сам факт использования парсера не доказывает файловый режим.

[money](../../order_document.py#L279) переводит пользовательское число в целые копейки через `Decimal(str(value))`, проверяет конечность, неотрицательность, не более двух десятичных знаков и верхний предел. `None`/пустое поле остаются отсутствующей суммой; ноль — настоящая сумма. `display_money` делит копейки на 100 для показа. Плавающий `float` не должен быть хранилищем фактической суммы.

`Path` задаёт структуру пути; `.relative_to(root)` проверяет принадлежность. Лексическая нормализация, `resolve()` и обход символических ссылок имеют разную семантику. В [MetadataStore.key](../../local_metadata.py#L70) используется лексическая абсолютная форма и NFC без обращения к существованию документа. Для файловой операции дополнительно проверяются реальные компоненты и запрет symlink. Смешивать эти проверки нельзя: SQLite-запись может быть нужна даже при временно недоступном iCloud.

NFC приводит эквивалентные Unicode-последовательности к устойчивому ключу. Это особенно существенно для русских имён на macOS. Сравнение только отображаемого названия не заменяет UUID и полный путь.

## Исключения и сохранение черновика

`raise OrderConflict(...)` сообщает вызывающему HTTP-слою о конфликте. `raise ... from None` скрывает лишнюю цепочку технической причины там, где сообщение должно быть безопасным и понятным. Это не означает, что исключения следует повсеместно подавлять.

[ManagerHandler.do_POST](../../server.py#L1946) преобразует известные ошибки в JSON. Браузерный `request` проверяет HTTP-статус и создаёт `Error` со свойством `status`. Таким образом, отказ SQLite или несовпадение revision не должны выглядеть как успешный ответ `200` с пустой карточкой.

Широкий `except Exception` встречается на границе фонового цикла, чтобы один сбой не уничтожил работника. Внутри бизнес-операции он не даёт права продолжать частично проверенную запись. Состояние ошибки сохраняется и доступно отдельному запросу интерфейса.

## Потоки, блокировки и отдельные процессы

`threading.Thread(..., daemon=True).start()` запускает функцию параллельно обработчикам HTTP. Общие словари состояния, события и очереди требуют собственного протокола координации. `threading.Event` одновременно предоставляет сигнал явного обновления и прерываемое ожидание; это отличается от бессрочного `sleep`.

`Lock` не допускает повторного захвата тем же потоком; `RLock` допускает вложенные вызовы под одной блокировкой. `BoundedSemaphore` ограничивает количество одновременно выполняемых действий. В проекте это применяется к превью и защищённым HTTP-соединениям. Блокировка Python координирует потоки процесса, а SQLite-транзакция — доступ к базе, в том числе из самостоятельного инструмента. Одна не заменяет другую.

[send](../../telegram_calendar.py#L217) выполняет последовательность PNG/тексты под `SEND_LOCK`, которую захватывает вызывающий HTTP-обработчик или обработчик команды. [process](../../telegram_calendar_commands.py#L50) дополнительно фиксирует состояние в базе, поскольку блокировка памяти исчезает при перезапуске.

`subprocess.run([...], input=..., capture_output=True, timeout=..., check=True)` ждёт дочерний процесс и получает его вывод. Список аргументов передаётся без shell-интерполяции. Ненулевой код при `check=True` становится исключением; `timeout` ограничивает ожидание. [build](../../native_renderers.py#L10) и [render](../../calendar_delivery.py#L94) используют это для Swift. `Popen` в `/api/open` запускает системное действие без ожидания закрытия пользовательского приложения.

## Генераторы и обходы

Списковое включение `[... for ... if ...]` строит список сразу. Генератор в `any(...)` останавливается на первом подходящем элементе. Это полезно при проверке видимости календарной строки: достаточно одного актуального невыполненного события. Но при операции, которой нужно проверить весь план до первой записи, раннее завершение проверки недопустимо; [changes](../../weekly_events_migration.py#L21) сначала готовит полный набор изменений.

`os.walk` может вернуть неполный обход с ошибками. Каталог задач хранит явное состояние полноты: отсутствие пути в неполном результате не доказывает его удаления. Это смысл `todo_missing_folders`, а не просто оптимизация списка.

## Как читать конкретный метод

Начни с его двух строк комментария, затем проверь аргументы и sentinel-значения, ранние отказы, блокировку/транзакцию, точные изменяемые поля, историю и возвращаемое состояние. После этого прочитай вызывающий HTTP-маршрут и браузерный обработчик ошибки. Для функции с файловым действием дополнительно найди журнал и восстановление.

[Справочник Python](../reference/README.md#python) содержит все именованные объявления собственного рабочего кода и эксплуатационных скриптов, включая вложенные функции и приостановленный модуль iPhone.
