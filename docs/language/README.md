# Реализация на уровне языков

Этот раздел отвечает на вопрос, **как именно конструкции языка реализуют поведение менеджера**. Дата среза — 3 ноября 2026 года. Примеры относятся к локальному коду проекта, а не к произвольной версии сторонней библиотеки.

| Документ | Что разбирать |
| --- | --- |
| [Python](python.md) | Модули, классы, self, контекстные менеджеры, транзакции, исключения, строгая валидация, потоки и процессы |
| [JavaScript](javascript.md) | Общий scope, замыкания, DOM, async/await, черновики, таймеры, гражданские даты, Worker и PNG |
| [SQLite и форматы](sqlite.md) | Строки, ключи, revision, JSON, BLOB, история, очереди, схемы и миграции |
| [Swift, C и запуск](swift-c.md) | Foundation/AppKit/WebKit, stdin/stdout, ARC, Codable, actor, атомарная запись, fork/exec и launchd |

Для каждого собственного Python-модуля, браузерного скрипта и нативного исходника создан [отдельный справочник](../reference/README.md). В нём: ссылка на файл, объявления и сигнатуры, двухстрочное назначение, непосредственные синтаксические вызовы и доступные сведения о возврате/исключениях. Это дополнение к объяснению, а не предположение о полном динамическом графе вызовов.

Начни с цепочки `static/app.js:saveCurrentStatus → server.py:ManagerHandler.do_POST → orders.py:OrderStore.save → sqlite3`. Затем сравни частичное сохранение недели с полной карточкой: одинаковый язык и одна база реализуют разные контракты изменения.
