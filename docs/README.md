## Правила и текущее приложение

Документ [«Структура папок»](folder-structure.md) описывает целевой порядок хранения документов. Наличие правила в документации само по себе не означает, что соответствующая проверка уже встроена в интерфейс.

Текущее состояние на дату этой версии:

| Возможность | Состояние |
| --- | --- |
| Дерево фактических папок, просмотр и фильтрация файлов | Реализовано |
| Служебные папки `#…`: заметка, исключение из регистрации и поиска заказов | Реализовано |
| Локальный список зарегистрированных заказов, статусы и финансы | Реализовано |
| Единый `!.txt`, восстановление и постоянная очередь выгрузки | Реализовано |
| Редактор заданий в `# work/# print` | Реализовано |
| Обратимые переносы по заранее подготовленному плану | Отдельный инструмент `folder_layout.py` |
| Отчёт по согласованной структуре | Отдельная проверка; отчёты сохраняются при соответствующей работе с архивом |
| Автоматическое распознавание всех уровней: клиент, объект, год, заказ, событие | Следующий этап разработки |
| Проверка структуры с подсказками непосредственно в интерфейсе | Следующий этап разработки |
| Автоматическое сканирование папок и заполнение описания печати | Не реализовано; кнопка «Позже» |
| Контекстное меню дерева для регистрации заказа | Следующий этап разработки |

Сейчас произвольная папка вне служебного поддерева может показывать форму карточки и кнопку регистрации. При регистрации нужно выбирать сам заказ. Ограничение регистрации по всем согласованным типам папок предстоит добавить вместе с распознаванием структуры. Поиск карточек и проверка структуры — разные действия: поиск восстанавливает записи по файлам карточек, проверка оценивает расположение и названия папок.

## Как поддерживать документацию

1. Новое решение пользователя записывается в соответствующий документ этого раздела.
2. Если правило влияет на последующие изменения проекта, одновременно обновляется `AGENTS.md`.
3. В [истории документации](CHANGELOG.md) указываются дата, версия и смысл изменения.
4. Изменения реализации отражаются в таблице состояния выше; планы сохраняются с явной пометкой.
5. Сведения о конкретных переносах остаются в журналах рядом с документами, а общие правила — здесь.

Для версий документации используется `MAJOR.MINOR.PATCH`: изменение несовместимого правила повышает `MAJOR`, новое согласованное правило или раздел — `MINOR`, уточнение формулировки — `PATCH`. Версия документации независима от версии приложения и формата `!.txt`.
