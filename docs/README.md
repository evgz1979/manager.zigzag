## Правила и текущее приложение

Документ [«Структура папок»](folder-structure.md) описывает целевой порядок хранения документов. Наличие правила в документации само по себе не означает, что соответствующая проверка уже встроена в интерфейс.

Клиенты, объекты и группы года показывают заметку без предложения добавить заказ. Заказ распознаётся по дате или числовому номеру с учётом расположения и непосредственных подпапок; годовое объединение отличается от отдельной работы за год. Регистрация и поиск карточек проверяют роль на сервере. Существующую ошибочную регистрацию можно снять с подтверждением. Полная проверка отклонений структуры и подсказки по неоднозначному архиву остаются следующим этапом. Поиск карточек и проверка структуры — разные действия.

## Как поддерживать документацию

1. Новое решение пользователя записывается в соответствующий документ этого раздела.
2. Если правило влияет на последующие изменения проекта, одновременно обновляется `AGENTS.md`.
3. В [истории документации](CHANGELOG.md) указываются дата, версия и смысл изменения.
4. Изменения реализации отражаются в таблице состояния выше; планы сохраняются с явной пометкой.
5. Сведения о конкретных переносах остаются в журналах рядом с документами, а общие правила — здесь.

Для версий документации используется `MAJOR.MINOR.PATCH`: изменение несовместимого правила повышает `MAJOR`, новое согласованное правило или раздел — `MINOR`, уточнение формулировки — `PATCH`. Версия документации независима от версии приложения и формата `!.txt`.
