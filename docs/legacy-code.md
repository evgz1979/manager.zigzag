# Старый, приостановленный и отдельно запускаемый код

Проверено по исходникам **3 ноября 2026 года**. Это реестр жизненного цикла, а не разрешение на удаление. В этой работе код не удалялся. «Нет в обычном пользовательском сценарии» и «никогда не вызывается» — разные утверждения.

## Как определялось использование

Проверены импорты Python, включая локальные импорты в методах, вызовы и ссылки на методы; script-теги HTML, вызовы браузерных модулей, Worker и отдельная HTML-страница; запуск Swift через Python; утилиты командной строки и копирование кода в самостоятельные журналы отката. Тестовая ссылка сама по себе не доказывает рабочую доступность. Проверка статическая: она не заменяет профиль исполнения M4 и не устанавливает, какие старые файлы реально остались в архиве.

[Таблица входящих импортов и отдельных точек запуска](reference/module-usage.md) даёт проверяемые свидетельства для каждого модуля.

Полностью ненужный собственный Python-модуль, который можно безопасно удалить по этим данным, **не подтверждён**. При этом ниже есть конкретные отключённые ветки и прежние форматы. Они остаются в дереве исходников и требуют отдельного решения при удалении.

## Устаревшие артефакты и специальные данные

`data/swift-cache` заменён `data/swift-cache-v2`: старый кеш мог содержать абсолютные пути из разных релизов. [build](../native_renderers.py#L10) больше его не выбирает. Автоматическая очистка старого кеша и старых бинарных файлов не добавлена. Это генерируемые данные установки, не отдельный Python-модуль.

`output/` содержит прежние иллюстрации проверок интерфейса. Они не подгружаются приложением и не доказывают вид текущей версии. `docs/history/` хранит прежние обзорные инструкции только для истории. `docs/CHANGELOG.md` описывает решения на дату записи; более позднее решение может их заменить.

`static/vendor/` содержит используемые локальные SheetJS и html2canvas. Это сторонние библиотеки с собственными лицензиями. Их минифицированные функции не покрываются нашим двухстрочным комментированием; ручное переписывание vendor ухудшило бы проверяемость происхождения.

`deadlineTravelPeriod` в `static/app.js` задаёт согласованную маркировку недель 14.12.2026–25.01.2027. Это ограниченный период, но код сейчас используется при построении кнопок недель и не является доказанным мусором. После периода потребуется отдельное решение о будущем отображении, а не незаметное удаление в документационной правке.

## Что остаётся архитектурным долгом

`server.py` совмещает HTTP, сборку представлений, фоновые циклы, старую файловую совместимость и macOS-интеграции. `static/app.js` совмещает состояние многих редакторов и связывает компоненты через глобальные имена. Эти большие файлы используются; размер не доказывает неактуальность. В документации они разобраны по сценариям и символам, рефакторинг не выполнялся.

Флаг `database_only` оставляет две модели хранения внутри некоторых адаптеров. Текущий сервер выбирает SQLite, но совместимые файловые тесты и первоначальный импорт продолжают обращаться к общим парсерам. Перед удалением старого режима нужны отдельный список поддерживаемых старых архивов и проверка восстановления.

Номер строки в ссылке фиксируется для этого среза кода и сдвигается при редактировании. Устойчивое имя символа приведено рядом; [проверка документации](development.md#проверка-документации) обнаруживает рассогласование инвентаризации.
