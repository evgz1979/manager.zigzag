# Разработка, проверки и поддержка документации

Правила генерации обновлены 5 ноября 2026 года. Рабочие данные M4 и файлы «Зигзаг» не нужны для анализа исходников и обновления справочников.

## Изолированная среда

Локальный `manager.ini` задаёт `data/dev-documents`, `127.0.0.1:8766`. Перед запуском проверь `ZIGZAG_DATA_ROOT` и `MANAGER_HOST`: окружение может переопределить INI. Не направляй тестовый процесс на рабочий архив ради проверки интерфейса.

```sh
mkdir -p data/dev-documents
python3 server.py
```

[Интерфейс разработки](http://127.0.0.1:8766). Сервер читает настройки при импорте, поэтому переменные тестового окружения задаются заранее. Для собственного эксперимента лучше временный корень, а не подмена рабочего пути или удаление базы.

Python-код приложения использует стандартную библиотеку; для нативных помощников нужны macOS SDK и `swiftc`. Браузеру не нужен Node: он требуется части тестов и инструменту инвентаризации JavaScript. Внешние библиотеки интерфейса лежат в `static/vendor` с лицензиями; не загружаются с CDN.

## Стиль двух строк в коде

Перед каждым собственным именованным классом/функцией рабочего Python, методом, вложенной именованной функцией, именованной JS-функцией/методом, Swift-типом/методом и C-функцией — две строки:

```python
# Меняет одну неделю срока без изменения даты сортировки заказа.
# Проверяет UUID/revision и сохраняет остальные поля в прежней транзакции.
def save_deadline_week(...):
```

Первая строка объясняет назначение, вторая — существенный контракт, возвращаемое состояние, ошибку, источник данных или взаимодействие. Не нужно заменять существующий docstring/комментарий, если он сохраняет дополнительные важные условия. Перед Python-декоратором комментарий относится ко всему объявлению. В Swift атрибут может предшествовать двум строкам перед типом.

JavaScript использует `//`; у метода внутри выражения допустим двухстрочный `/* ... */`, чтобы сохранить границу выражения и автоматическую расстановку `;`. Анонимные event callbacks описываются через владельца. Вычисляемое Swift-свойство `body` — часть описания типа экрана. Тестовые методы и vendor не покрываются правилом рабочего кода; их назначение объясняется отдельно.

Комментарии должны оставаться согласованными с телом. Автоматическая проверка считает покрытие и ссылки, но не доказывает правдивость русского текста. Не следует писать «данные не меняются» только потому, что функция называется `read`: открытие адаптера может готовить схему или выполнять первоначальный импорт.

## Проверка документации

`scripts/build_documentation.py` читает собственные исходники, AST Python, объявления Swift/C и Babel AST JavaScript. Приложение не импортируется, база не открывается, сервис не запускается. Файлы создаются только в `docs/reference`; `--check` ничего не переписывает.

Нужны Node и Babel bundle из установленного Playwright. Можно использовать Node/пакеты из bundled runtime Codex, который возвращает `load_workspace_dependencies`, либо своё окружение разработки. Путь к библиотеке задаётся явно или через `MANAGER_DOCUMENTATION_BABEL`; при доступном Playwright достаточно `NODE_PATH` с его каталогом пакетов.

```sh
# Если node и Playwright доступны в окружении:
python3 scripts/build_documentation.py
python3 scripts/build_documentation.py --check
```

Для нестандартного окружения передай `--node <абсолютный-путь-к-node>` и `--babel <путь-к-playwright/lib/transform/babelBundle.js>`. Инструмент не устанавливает зависимости через сеть и не добавляет Node в рабочий запуск менеджера.

Генератор обновляет страницы модулей, HTTP-ветки, SQL DDL и компактный `inventory.json` версии 2. В индексе остаются путь, квалифицированное имя, тип и якорь; номера строк, дата сборки и хеши исходных файлов не сохраняются. Страницы сортируют объявления по имени, HTTP/SQL ссылаются на владельца по постоянному якорю. Полезные сигнатуры, комментарии, вызовы и явные return/raise остаются. Проверка сравнивает заново построенные документы, обнаруживает отсутствующие две строки комментария, пропавшие объявления, устаревшие/лишние страницы, несуществующие локальные файлы и символы. Внешние сайты и произвольные heading-якоря не проверяются.

После изменения кода сначала исправь комментарий и затронутые объясняющие документы, затем пересобери справочник. Для тематического текста указывай функцию и постоянную ссылку вида `reference/python/invoices.md#symbol-InvoiceStore.plan`. Вставка пустых строк или обычного комментария перед кодом должна оставлять весь справочник побайтно прежним. Небольшое изменение тела функции обычно меняет только страницу её модуля; реальное изменение API, DDL или зависимостей меняет соответствующий справочник.

## Проверки приложения

```sh
python3 -m unittest discover -s tests -v
```

Node должен быть в PATH: часть Python-тестов запускает `tests/*.cjs`, иначе эти проверки пропускаются через `skipUnless`. Сценарии CJS проверяют календарь, таймеры окна задач, раскладку/период, деньги и просмотр таблиц. Нативные тесты могут пропускаться вне macOS. В отчёте фиксируй фактическое число выполненных и пропущенных, а не старый счётчик из предыдущего деплоя.

```sh
sh mobile/check.sh
python3 mobile/protocol_check.py
```

Это проверки сохранённого, приостановленного мобильного кода. Они не включают обмен на M4, не подписывают приложение и не доказывают доставку через iCloud. Большинство Python-тестов использует TemporaryDirectory, искусственные карточки и подменённые внешние вызовы.

При чистом комментировании полезнее доказать неизменность AST Python/JavaScript и исполняемых токенов Swift/C, чем добавлять тест, который лишь повторяет текст комментария. Полный существующий набор всё равно нужен из-за чтения/упаковки исходников и нативной сборки.

## Проверка ссылок на объявления

У каждого объявления есть явный постоянный HTML-якорь `symbol-Полное.имя`; вложенные JavaScript-функции и Swift-методы квалифицируются владельцем. Перегрузки одного имени получают дополнительный идентификатор из сигнатуры, независимо от порядка и строк. Актуальные документы ссылаются на эти описания, откуда доступен исходный файл. Переименование/удаление символа требует обновить ссылки; `--check` обнаруживает оставшиеся старые цели.

Точную физическую строку, когда она нужна для открытия редактора, вычисляй без записи справочника:

```sh
python3 scripts/build_documentation.py --locate invoices.py::InvoiceStore.plan
```

Команда использует те же параметры `--node`/`--babel` и печатает текущую позицию с сигнатурой. Новые ссылки `#Lчисло` вне `docs/history/` запрещены проверкой. Хеши, защищающие релизы, резервные копии и пользовательские данные, сохраняются независимо от формата документации.

Регрессии генератора проверяет `python3 -m unittest discover -s tests -p test_documentation.py -v` при доступных Node и Playwright Babel: сдвиг строк для всех поддерживаемых языков, стабильность HTTP/SQL и индекса, локальная правка тела, пропавший символ/якорь, нарушение двухстрочного комментария и точный `--locate`.

Исторические снимки в `docs/history` сохраняют формулировки и ссылки своей эпохи. Их файл-цель должна существовать, но обещания прежнего статуса не трактуются как текущая проверка. Новые сведения о работающем M4 указывай с фактической датой проверки.

## Развёртывание

Проверенный код доставляется `scripts/deploy.py`, удалённая часть — `scripts/deploy_remote.py`. Обычный пакет не включает рабочий `data` и документы. Перед переключением собираются Swift-помощники и проверяется совместимость контрактов базы. Изменение комментария Swift меняет хеш и имя бинарного файла, поэтому сборка требуется и для такого релиза.

Этот раздел не означает, что нужно деплоить документационную правку автоматически. Для состояния сервиса и разрешённого отката используй [операции](operations.md#деплой-на-m4). Никогда не считай открытый LAN health проверкой защищённого внешнего порта.

## Порядок дальнейшей актуализации

1. Изменив правило, обнови один авторитетный документ пользователя и AGENTS, если правило влияет на будущую работу.
2. Изменив реализацию, проверь соответствующую цепочку в `flows.md`, архитектуру и языковой разбор.
3. Поддержи двухстрочное описание и перегенерируй справочник.
4. Запусти проверку документации и нужные существующие тесты.
5. Запиши в CHANGELOG, что проверено локально, что развёрнуто и что осталось непроверенным.

Версии документации — `MAJOR.MINOR.PATCH`: несовместимое правило / новый раздел или правило / уточнение. Версия документации не обещает соответствующий публичный релиз приложения.
