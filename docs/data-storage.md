# Хранение и восстановление данных

Версия: **1.1.1**. Обновлено: **18 октября 2026 года**. Статус: **согласованные правила и описание текущего хранения**.

## Где находится информация

Документы остаются в корне, заданном в `manager.ini`. Карточки, заметки, описания, ссылки, вложения и история находятся рядом с теми документами, к которым относятся. После выгрузки папку заказа можно прочитать в Finder или на iPhone без запуска менеджера.

В каталоге кода находятся приложение, настройки, технические кеши и локальная база `data/`. Рабочая информация не хранится только в браузере или памяти процесса.

| Данные | Рабочий источник | Роль файлов папки |
| --- | --- | --- |
| Зарегистрированный заказ | Локальная SQLite-база | `!.txt` — выгрузка для чтения и восстановления |
| Карточка ещё не зарегистрированного заказа | Файлы папки | Внешние изменения `!.txt` учитываются |
| Заметка служебной папки `#…` | Файлы папки | Редактируемый `!.txt` без полей заказа |
| Задание на печать | Сам файл задания | Название, ссылка и описание сохраняются в нём |

Названия технических файлов и каталогов в документах — по-английски, с начальной точкой. Исключение — видимый `!.txt`, единая карточка папки. Названия пользовательских документов и согласованных папок `#…` этому правилу технических имён не подчиняются.

## Единый файл `!.txt`

Формат — обычный UTF-8. Текущая версия формата: **2**. Она независима от версии этой документации.

Пример карточки заказа без служебных сведений регистрации:

```text
КАРТОЧКА ЗАКАЗА

[Заказ]
Название: Перегородка
Статус: В работе

[Финансы]
Сумма заказа: 100 000,00 ₽
Затраты: 60 000,00 ₽
Прибыль: 40 000,00 ₽
Оплачено: 50 000,00 ₽
Остаток оплаты: 50 000,00 ₽

[Заметка]
> Согласовать размеры.
> Позвонить перед выездом.

[Служебное]
Формат: 2

```

В `[Заказ]` находятся название и русский статус; выгрузка зарегистрированного заказа также может содержать клиента и путь. В `[Финансы]` записываются суммы и вычисляемые итоги. Для простой карточки без финансов этот раздел может отсутствовать.

Каждая строка заметки начинается с `> `, включая пустую строку. Это сохраняет переносы, пустые строки и текст, похожий на заголовки разделов. При редактировании в текстовой программе этот префикс нужно сохранять.

В `[Служебное]` зарегистрированной карточки дополнительно записываются идентификатор, версия и время изменения. Отдельный JSON для восстановления не создаётся. Дополнительные разделы, например `[Замеры]`, `[Материалы]`, `[Доставка]`, сохраняются при чтении, редактировании, выгрузке и восстановлении базы.

Карточка и прежние служебные файлы не включаются в список вложений приложения.

## Заметка служебной папки

```text
ЗАМЕТКА ПАПКИ

[Заметка]
> Счёт отправлен клиенту.

[Служебное]
Формат: 2

```

У служебной папки нет статуса заказа, финансов или регистрации. Заметку можно менять через менеджер и вне него. Дополнительные разделы сохраняются.

Согласованное исключение для нынешних тестовых данных: прежние поля заказа в служебных `#…` убираются из их карточек, а тестовые регистрации этих папок удаляются из базы без выгрузки поверх файлов. Заметка берётся из папки; реальные счета, макеты и другие документы сохраняются. Это исключение не разрешает удалять реальные данные обычных заказов или сбрасывать всю базу.

## Зарегистрированные заказы

База находится в `data/orders-<хеш-корня>.sqlite3`. Разным корням документов соответствуют разные базы.

Список, поиск по зарегистрированным заказам, фильтры и сохранение карточки работают с локальной базой и не должны обращаться к iCloud. Дерево и вложения загружаются отдельно из документов.

После изменения:

1. Карточка и новая версия фиксируются в SQLite.
2. Ожидающая выгрузка сохраняется в самой базе.
3. Полный `!.txt` атомарно записывается в папку заказа.
4. При ошибке база сохраняет актуальные данные, очередь и причину ошибки.
5. Повторная попытка выполняется после запуска, периодически и по кнопке выгрузки. Сейчас период — 15 секунд.

Пока есть невыгруженные изменения, база является необходимой копией актуальных данных. Удалять `data/` или заменять базу в таком состоянии нельзя. Успешная запись на локальный диск не подтверждает завершение передачи в iCloud: облачную синхронизацию выполняет система.

Файл зарегистрированного заказа предназначен для чтения. Его содержимое не импортируется поверх более новой карточки в базе. Версии защищают от сохранения устаревшей карточки из другой вкладки.

## Снятие регистрации

Действие **«Убрать из списка заказов»** доступно в открытой карточке. В компактной таблице заказов это действие не показывается. Оно требует подтверждения с названием и путём папки. Отмена не меняет регистрацию.

Снимается только регистрация выбранной папки. Папка, вложения, заметка, финансы и дополнительные разделы сохраняются. Регистрации вложенных заказов остаются. Например, объект `Виктория/Коштоянца` можно убрать из списка, сохранив отдельный заказ внутри него.

Изменение фиксируется локально с новой версией записи. Вместо удаления актуальной карточки из базы запись сохраняется как снятая с регистрации; полные данные выгружаются обычной устойчивой очередью. Работа возможна при временно недоступной папке. Ожидающее или неудачное сохранение снятия регистрации отображается в общем списке.

В `[Служебное]` файла `!.txt` записывается **`В списке заказов: нет`**. Это признак явного снятия регистрации, который сохраняется при внешнем редактировании заметки. В интерфейсе папки остаётся заметка без формы заказа; прежние данные карточки остаются в файле.

Повторный поиск пропускает снятую регистрацию как по локальной записи, так и по признаку в `!.txt`. Поэтому такая папка не появляется снова и при восстановлении базы из документов. Файл можно снова зарегистрировать только явным действием **«Добавить в список заказов»**. При повторном добавлении восстанавливаются сохранённые поля и дополнительные разделы; ещё не выгруженные актуальные данные базы имеют приоритет перед старой копией файла.

Снятие регистрации проверяет версию карточки. Если её изменили в другой вкладке, действие отклоняется до обновления данных. Несохранённый ввод текущей карточки сохраняется перед подтверждённым снятием регистрации. До завершения выгрузки редактирование заметки снятой папки ожидает сохранения полной карточки.

## Статусы и деньги

Статусы: **Новый**, **Замеры**, **В работе**, **В цех**, **Монтаж**, **На оплате**, **Готово**, **Отменён**.

В карточке доступны сумма заказа, затраты и оплачено. Прибыль равна сумме минус затраты; остаток оплаты — сумме минус оплачено. Отрицательный остаток обозначает переплату.

Пустая сумма означает «не указано». Ноль вводится явно. Деньги хранятся целыми копейками; ввод допускает запятую, точку и пробелы между разрядами. Если для итога не хватает исходных значений, он остаётся неопределённым.

## Прежние форматы

Для переноса поддерживаются `!status.txt`, `!order.txt`, `.order.json`, `status.txt`, `.status.txt`.

Существующий `!.txt` имеет приоритет. После успешной атомарной записи единого файла исходные байты прежних рабочих файлов сохраняются в `.order-history` внутри той же папки, затем прежние рабочие файлы убираются. При ошибке записи они остаются на месте.

Переход формата не должен затирать существующие локальные правки. Прежние записи `data/statuses.json` переносятся с сохранением исходного JSON в скрытом архиве корня; несопоставленные данные остаются для разбора.

## Регистрация и восстановление

При добавлении заказа восстанавливаются все поля и дополнительные разделы из `!.txt`; прежние форматы также учитываются.

Явный поиск карточек импортирует отсутствующие записи. Он не должен считать произвольную папку заказом только из-за её глубины. Текущий поиск использует наличие файлов карточки или прежнего статуса, пропускает скрытые каталоги, служебные поддеревья `#…` и символические ссылки. Существующие записи базы не заменяются. Копия папки получает отдельную идентичность заказа.

После полной успешной выгрузки данные заказов можно восстановить из папок. До неё сохраняется локальная база с очередью. Перенос зарегистрированного заказа требует отдельного согласования путей базы и документов: инструмент раскладки сам базу не переписывает. Подробнее — [работа с архивом](operations.md).

## Задания на печать

Редактор применяется к `# work/# print`; пробел после `#` необязателен. Название, ссылка и описание находятся в самом файле задания. История прежних версий хранится рядом в `.print-history`, которая не входит в активные задания.

Новые имена: `print - ГГГГ-ММ-ДД`, дата по Москве. Расширение берётся из существующего образца. При совпадении добавляется номер; существующий файл не перезаписывается. Название внутри задания не меняет его имя на диске.

Описание заполняется вручную. Сканирование папок для заполнения описания пока не реализовано.
