# Правила проекта «Менеджер заказов Зигзаг»

## Постоянная документация

Пользовательские и проектные правила записаны в [docs/README.md](docs/README.md): [структура папок](docs/folder-structure.md), [хранение данных](docs/data-storage.md), [операции и откат](docs/operations.md). Перед изменениями соответствующего поведения сверяйтесь с этими документами. Новые согласованные решения обновляйте в документации и в применимых инструкциях этого файла, с записью в [docs/CHANGELOG.md](docs/CHANGELOG.md). Состояние реализации указывается отдельно: наличие правила в документации не означает готовую проверку в интерфейсе.

## Хранение рабочей информации

Пользователь должен иметь возможность открыть папку заказа в Finder и прочитать всю выгруженную информацию без запуска менеджера. По прямому запросу пользователя зарегистрированные заказы ведутся в локальной SQLite-базе с очередью выгрузки в каталог документов; правила ниже различают зарегистрированные заказы и остальные папки.

- Статусы, заметки, названия, описания, ссылки, вложения и история изменений сохраняются рядом с теми документами, к которым относятся.
- Служебные файлы и каталоги называйте по-английски и начинайте их имена с точки, чтобы они были скрыты в Finder. Исключение — `!.txt`: это единая видимая карточка папки, доступная с iPhone. Это правило не требует переименовывать пользовательские документы.
- Используйте читаемые обычными программами файлы с понятными именами и простыми форматами. Текстовые данные должны быть доступны для просмотра и редактирования вне приложения.
- Вся информация карточки папки — статус, название, заметка, финансы и будущие блоки — хранится в едином `!.txt`. Разделы: `[Заказ]`, `[Финансы]`, `[Заметка]`, `[Служебное]`. Названия статусов русские; заметка многострочная, каждая строка начинается с `> `, чтобы сохранить произвольный текст. Служебный раздел содержит формат и, для зарегистрированных заказов, идентификатор, версию и время. Отдельный JSON для восстановления не создаётся. Неизвестные дополнительные разделы сохраняйте при чтении, редактировании, выгрузке и восстановлении базы.
- Прежние `!status.txt`, `!order.txt`, `.order.json`, `status.txt`, `.status.txt` поддерживаются для переноса. После успешной атомарной записи `!.txt` сохраняйте их исходные байты в скрытой `.order-history` внутри той же папки и убирайте прежние рабочие файлы. При ошибке записи не трогайте исходные файлы. Существующий `!.txt` имеет приоритет. Карточка и прежние служебные файлы не показываются в списке вложений менеджера.
- Задания на печать содержат название, ссылку и описание в самом файле задания. Их резервные копии находятся в `.print-history` рядом с заданиями; приложение не включает этот служебный каталог в список активных заданий.
- Для зарегистрированных заказов база в локальном `data/orders-<root-hash>.sqlite3` — рабочий источник данных. Список, фильтры и сохранение карточки не должны обращаться к iCloud. После изменения автоматически выгружайте единый `!.txt` с полной карточкой и данными для восстановления. Файл зарегистрированного заказа предназначен для чтения; не импортируйте его поверх более новых данных базы. Отмечайте ожидающую или неудачную выгрузку, повторяйте после ошибки и перезапуска. Не удаляйте базу с невыгруженными изменениями.
- Для остальных папок файлы остаются источником истины; учитывайте внешние изменения `!.txt`. При добавлении заказа восстанавливайте все поля и дополнительные блоки из `!.txt`, также учитывайте прежние файлы карточки. Явный поиск заказов импортирует отсутствующие карточки из `!.txt` и папки с прежним файлом статуса; произвольные папки автоматически заказами не считаются.
- Общая таблица заказов должна быть максимально компактной: без кнопок снятия регистрации в строках, с небольшими отступами. Действие снятия регистрации находится в открытой карточке заказа.
- Снятие регистрации выполняется действием «Убрать из списка заказов» с обязательным подтверждением и проверкой версии. Снимается только выбранная запись: папка, вложения, полная карточка и регистрации дочерних заказов сохраняются. Изменение фиксируется в базе, включая устойчивую очередь выгрузки; невыгруженную карточку не удаляйте. В `[Служебное]` файла `!.txt` записывайте `В списке заказов: нет`. Поиск и восстановление не должны регистрировать такую папку обратно; повторное добавление допускается только явно пользователем. После снятия в папке показывается заметка, а сохранённые поля восстанавливаются при ручном добавлении.
- Не храните рабочую информацию только в браузере или оперативной памяти. Для зарегистрированных заказов допустима временная задержка выгрузки из устойчивой SQLite-базы; очередь должна сохраняться в самой базе.
- При изменении формата сохраняйте прежние данные и переносите их в каталоги документов без потери информации и без перезаписи существующих локальных правок.
- В каталоге кода хранятся код, настройки, технические кеши и локальная база зарегистрированных заказов в `data/`. После успешной выгрузки заказы целиком восстанавливаются из `!.txt`; пока есть очередь выгрузки, база содержит актуальную версию, её необходимо сохранять.

## Структура каталогов

Код находится отдельно в `~/Documents/manager`. Корень документов задаётся в `manager.ini`; путь не прошивается в коде.

В корне документов лежат клиенты. Корневые папки, начинающиеся с `#`, — общая информация, представленная кнопками над деревом. Папки с `#` сортируются выше остальных; при распознавании специальных папок пробел после `#` необязателен.

Папки с `#` на любой глубине и их содержимое — служебные, не заказы. В них показывается только заметка без карточки заказа, статуса, финансов и регистрации в списке заказов. `# bills` содержит счета для родительского заказа, `# cdr` — файлы CorelDraw. Заметка хранится в `!.txt` с разделами `[Заметка]` и `[Служебное]`; внешние изменения учитываются. По указанию пользователя прежние статусы, финансы и регистрации служебных папок считаются тестовыми: поля заказа удаляются из их `!.txt`, регистрации удаляются из базы без выгрузки. Источник заметки — файлы папки; заметка и дополнительные разделы сохраняются. Реальные документы не меняются. Поиск заказов пропускает служебные поддеревья.

Основная структура: клиент → объект → необязательная папка года → заказ по дате → события и служебные папки. Объекты сохраняются отдельным уровнем; существующие смысловые группы объектов не смешиваются. Слева дерево папок, справа содержимое выбранной папки.

Корневые папки с двумя и более начальными цифрами — общие группы для мелких заказов. Такие же общие папки и нумерованные заказы (`00 - разное`, `00001 - …`) допустимы внутри клиента без привязки к конкретному объекту. Их номера сами по себе не означают ошибку или дату. Папку года и дату распознавайте до проверки общего числового префикса.

У заказов допустима неполная дата: `2026-00-00` означает год, `2026-09-00` — месяц. Краткая запись `26 00 00` также обозначает приблизительную дату 2026 года, а не отдельный точный день. Данные файлов могут помочь оценить период, но дата копирования или отдельного старого макета не доказывает дату заказа. Существующие пользовательские даты не уточняйте автоматически. Основания для приблизительно назначенных дат записывайте в журнал.

В заказе папки с `#` служебные, папки `00`, `01`, `02 - …`, `00-01 …` — события. При проверке структуры ограничивайтесь этим уровнем; глубже события и служебной папки не обходите. Для оценки дат по отдельному запросу допустимы метаданные файлов непосредственно внутри события, без рекурсивного просмотра. Корневые `#…` и их поддеревья полностью исключайте из проверок и раскладки.

Структурные проверки только сообщают о несоответствиях. Переносы выполняются по отдельному запросу пользователя. Любой разрешённый перенос или создание каталога документов записывайте до и после операции в устойчивый читаемый журнал в `.folder-layout-history` внутри корня документов; рядом сохраняйте исходную структуру, план, результат и средство отката. Не перезаписывайте и не объединяйте существующие пути. Откат идёт в обратном порядке, сохраняет новые пользовательские файлы и останавливается при конфликтах. Содержимое файлов при раскладке не меняется.

В `# work/# print` — задания на широкоформатную печать. Новые файлы называются `print - ГГГГ-ММ-ДД` по московскому времени с расширением существующего образца. При совпадении имени добавляется номер, существующие файлы не перезаписываются.

Автоматическое сканирование папок и заполнение описания пока не реализуются: в редакторе оставлена неактивная кнопка с пометкой «Позже».
